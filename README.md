# 衡常 · 饮食与运动手账

一个为个人日常使用制作的中文饮食、运动与能量收支网站。无广告，无追踪，无构建依赖，适配电脑与手机。

## 可以做什么

- 早餐、午餐、晚餐与加餐：按实际克数换算热量、蛋白质、碳水和脂肪；支持编辑、删除后撤销、复制其他日期餐食。
- 18 种经过来源核对的参考食物、自定义包装营养标示、搜索与收藏。可查看每条内置食物的来源；生熟状态在名称中注明。
- 8 类运动预设与自定 MET，按时长、体重计算；也可输入运动设备提供的活动热量。
- 每日收支、营养目标、日终总结、体重、饮水和简短日记。
- 近 7 / 30 天摄入与体重趋势、完整日期的平均收支和每日明细。
- 浏览器自动保存、完整 JSON 导出与合并恢复、Excel 可读 CSV、导入前恢复副本。
- 可选 GitHub 云备份与恢复：主动上传个人记录，支持单独的私有数据仓库，上传前显示仓库可见性和目标路径。
- 首次联网访问并缓存成功后可离线使用；离线不能执行 GitHub 备份。

## 第一次使用

1. 在“个人与目标”填写年龄、身高、体重与日常活动，或直接填入自己的基础日消耗。
2. 录入三餐和运动，按实际分量调整。内置库没有的食物可根据包装营养标示创建。
3. 完成三餐后点击“结束当天记录”，查看日终小结。
4. 定期在“数据与备份”中导出 JSON。更换设备时导入，或使用 GitHub 备份恢复。

网站初始为空白，没有预置的个人身体资料或模拟饮食记录。

## 数据保存与 GitHub 备份

个人资料、饮食和运动默认保存在当前浏览器 `localStorage`，不自动写入代码仓库。不同设备、不同浏览器和不同网站地址之间不会自动共享记录。清理浏览器数据会影响本地记录，请定期备份。

GitHub 备份需要你自行配置仓库、分支、JSON 路径以及只对该仓库具有 Contents 读写权限的 fine-grained token。仓库须已有目标分支。令牌仅在本次操作内存中使用，不持久保存、不写入 JSON 或仓库。使用公开仓库时，个人记录以及 Git 历史也会公开；可以选择单独的私有数据仓库。

恢复时先校验数据格式并显示天数及重复日期，再由你确认合并。相同日期采用备份中的整日记录，其他日期保留；导入前自动保留一个本地恢复副本。网站不会把访问令牌写入备份。

## 计算口径

```text
食物营养 = 每 100g 营养值 × 实际可食克数 ÷ 100
静息代谢估计 = 10×体重kg + 6.25×身高cm − 5×年龄 + 参数
公式参数：男性 +5；女性 −161
基础日消耗 = 静息代谢估计 × 不含单独训练的日常活动系数
运动总消耗 = MET × 3.5 × 体重kg ÷ 200 × 分钟
运动净增加 = (MET−1) × 3.5 × 体重kg ÷ 200 × 分钟
每日缺口 = 基础日消耗 + 运动净增加 − 饮食摄入
基础摄入目标 = 基础日消耗 − 自定目标缺口
```

直接填写基础日消耗时优先使用该值。运动设备模式应录入“活动热量 / 净消耗”，不要填含静息消耗的全天总热量。手动净消耗无法还原运动总消耗，该总值显示为未知。日常活动系数仍可能与专项运动重叠，请按实际情况设置。摄入基础目标不自动增加运动热量。

每日首次记录保存当时的个人参数，避免以后改变资料时重算全部历史。修改个人资料会更新今天的参数；已经保存的运动体重保留。结束记录表示用户确认当日已记完整，之后仍可修改。

膳食纤维只合计已核实部分，未核实项为 `null`，界面提示缺失。所有能量值都是估算。日终建议是本地规则对比自定目标，不是医学诊断或个体营养处方。公式用于一般成人；未成年人、孕哺期或特殊营养需求应使用专业人员给出的目标。

## 来源与功能参考

- [USDA FoodData Central](https://fdc.nal.usda.gov/) 与 [USDA SR28](https://www.ars.usda.gov/ARSUserFiles/80400525/Data/SR/SR28/)：内置食物每 100g 营养数据，每条食物附具体记录或 PDF 链接。
- [Mifflin 等，1990](https://pubmed.ncbi.nlm.nih.gov/2305711/)：静息代谢方程。
- [2024 Adult Compendium](https://pacompendium.com/adult-compendium/)：运动 MET。2024 快走 5.6–6.3 km/h 采用 4.8 MET。
- [Cooper Institute](https://www.cooperinstitute.org/blog/using-met-minutes-to-track-volume-of-physical-activity)：MET 能量换算参考。
- [Cronometer Diary](https://support.cronometer.com/hc/en-us/articles/360018171731-Diary-Overview)、[wger](https://github.com/wger-project/wger)：参考分餐日记、营养汇总、训练与体重趋势的功能思路。本网站为独立实现，未复制其源码或视觉素材。

## 本地运行和验证

这是静态 ES module 网站，使用任意静态 HTTP 服务打开目录即可；不要直接双击 `index.html`（`file://` 下 ES modules 和离线缓存可能不可用）。Node.js 22+ 可运行以下计算与数据校验测试，无需安装依赖：

```text
node --test tests/*.test.mjs
```

## GitHub Pages 发布

将这些文件置于仓库根目录，然后进入仓库 Settings → Pages → Build and deployment，选择 Deploy from a branch、`main`、`/(root)` 并保存。根目录的 `.nojekyll` 让 GitHub 直接发布静态资源。

GitHub Free 的免费 Pages 发布通常需要公开仓库。已有私有仓库可在支持私有仓库 Pages 的套餐中使用，或将不含个人记录的站点代码单独放在公开仓库。详见 [GitHub 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

网站采用相对资源路径，可部署到 `https://用户名.github.io/仓库名/` 子路径。离线缓存仅处理应用静态文件，不缓存 GitHub API 返回的个人记录。
